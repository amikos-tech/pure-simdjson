<objective>
Implement `AtPathAll` (DOM-03), the one genuinely new transport shape in Phase 12: wildcard path
matching (`.items[*].id`) that returns an ordered set of long-lived, independently-held `Element`s
rather than a single result or a transient borrowed span.

Purpose: Phase 8's borrowed-frame-span pattern (`psdj_internal_materialize_build`) is unsuitable here
because wildcard results must survive and be independently usable after the call returns (D-03),
unlike materializer frames which are invalidated by the next call on the same doc. This plan
implements the bulk-transport design RESEARCH.md specified: a transient C++ scratch vector of
json_index values, converted synchronously into a Rust-owned, heap-allocated `Vec<ValueView>` before
the FFI call returns, tracked in a new, separate allocation table and freed via a new companion to
`bytes_free`.
Output: `pure_simdjson_element_at_path_wildcard` and `pure_simdjson_value_views_free` wired
end-to-end, with double-free/mismatched-length-free rejection proven by Rust integration tests.
</objective>

```cpp
pure_simdjson_error_code_t psimdjson_element_at_path_wildcard_indices(
    psimdjson_doc *doc, uint64_t json_index,
    const uint8_t *path_ptr, size_t path_len,
    const uint64_t **out_indices, size_t *out_count
) noexcept {
  try {
    if (doc == nullptr || out_indices == nullptr || out_count == nullptr) return invalid_argument();
    if (path_len != 0 && path_ptr == nullptr) return invalid_argument();
    *out_indices = nullptr;
    *out_count = 0;
    wildcard_build_guard guard(doc);
    if (!guard.acquired()) return PURE_SIMDJSON_ERR_PARSER_BUSY;
    const auto path = path_len == 0 ? std::string_view{}
        : std::string_view(reinterpret_cast<const char *>(path_ptr), path_len);
    std::vector<simdjson::dom::element> matches;
    const auto error = element_at(doc, json_index).at_path_with_wildcard(path).get(matches);
    if (error != simdjson::SUCCESS) return map_error(error);
    doc->wildcard_indices.clear();
    doc->wildcard_indices.reserve(matches.size());
    for (const auto &element : matches) { doc->wildcard_indices.push_back(element_json_index(element)); }
    if (!doc->wildcard_indices.empty()) {
      *out_indices = doc->wildcard_indices.data();
      *out_count = doc->wildcard_indices.size();
    }
    return PURE_SIMDJSON_OK;
  } PSIMDJSON_CATCH_CPP_EXCEPTIONS(__func__)
}
```

```rust
pub(crate) fn bytes_free(ptr: *mut u8, len: usize) -> pure_simdjson_error_code_t {
    if ptr.is_null() { return if len == 0 { err_ok() } else { err_invalid_argument() }; }
    if len == 0 { return err_invalid_argument(); }
    {
        let mut registry = registry_guard();
        match registry.byte_allocations.remove(&(ptr as usize)) {
            Some(registered_len) if registered_len == len => {}
            Some(registered_len) => {
                registry.byte_allocations.insert(ptr as usize, registered_len);
                return err_invalid_handle();
            }
            None => return err_invalid_handle(),
        }
    }
    unsafe { drop(Vec::from_raw_parts(ptr, len, len)); }
    err_ok()
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rust registry -> Go caller | A Rust-owned heap array crosses back into Go as raw pointer+count and must be freed exactly once |
| C++ bridge -> Rust registry | A doc-owned transient scratch vector is read synchronously within one call; it must never be read after the call returns |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-BULK | Tampering | pure_simdjson_value_views_free double-free / mismatched-length free | mitigate | Exact pointer+length match required against a dedicated view_array_allocations registry table before Vec::from_raw_parts reconstruction, mirroring bytes_free/byte_allocations verbatim; proven by dedicated Rust integration tests in Task 2 |
| T-12-07 | Tampering | Reading doc->wildcard_indices after the guard-scoped call returns (stale scratch buffer) | mitigate | The Rust registry function reads the returned (ptr, count) slice SYNCHRONOUSLY inside the same with_resolved_view closure that made the FFI call, before returning; the doc-owned scratch vector is never touched again after that point |
| T-12-08 | Denial of Service | Adversarial deeply-nested or huge-fanout JSON producing an unexpectedly large wildcard match Vec allocation | accept | Bounded by the existing parse-time depth/capacity limits (Phase 11 ErrDepthLimitExceeded / ErrCapacityLimitExceeded); no new unbounded amplification vector — match count cannot exceed the number of nodes already accepted at parse time |
| T-12-09 | Denial of Service | Concurrent wildcard calls on one document racing its scratch vector | mitigate | The Rust registry mutex remains held from view resolution through native call and synchronous index copying, serializing same-document calls; wildcard_build_guard is retained only as a same-call re-entrancy backstop. A concurrent Rust integration test proves both calls complete without racing or relying on PARSER_BUSY |
