From element.go (Object.GetField, ~line 369-392 — the exact no-panic-safe-twin shape Array.At
copies, per D-04):
```go
func (o Object) GetField(key string) (Element, error) {
	doc, err := o.element.usableDoc()
	if err != nil { return Element{}, err }
	if ffi.ValueKind(o.element.view.KindHint) != ffi.ValueKindObject { return Element{}, ErrWrongType }
	view, rc := doc.parser.library.bindings.ObjectGetField(&o.element.view, key)
	runtime.KeepAlive(doc)
	if err := normalizeIteratorError(doc, rc); err != nil { return Element{}, err }
	return Element{doc: doc, view: view}, nil
}
```
Array.At uses plain `wrapStatus(rc)`, not `normalizeIteratorError` (no iterator-lease semantics
involved).

From element.go (Type/TypeErr, ~line 101-148 — the EXACT panic-safe dual-method shape Array.Len/
LenErr and Object.Size/SizeErr copy):
```go
func (e Element) Type() ElementType {
	kind, err := e.TypeErr()
	if err != nil { return TypeInvalid }
	return kind
}

func (e Element) TypeErr() (ElementType, error) {
	doc, err := e.usableDoc()
	if err != nil { return TypeInvalid, err }
	kind, rc := doc.parser.library.bindings.ElementType(&e.view)
	runtime.KeepAlive(doc)
	if err := wrapStatus(rc); err != nil { return TypeInvalid, err }
	...
}
```

From element.go (AsArray/AsObject, ~line 287-311 — the kind-check-after-usableDoc shape reused by
every typed accessor, including these new ones):
```go
func (e Element) AsArray() (Array, error) {
	if _, err := e.usableDoc(); err != nil { return Array{}, err }
	if ffi.ValueKind(e.view.KindHint) != ffi.ValueKindArray { return Array{}, ErrWrongType }
	return Array{element: e}, nil
}
```

Bindings methods available from plan 12-05: `ArrayAt(view *ffi.ValueView, index uint64) (ffi.ValueView,
int32)`, `ArrayLen(view *ffi.ValueView) (uint64, int32)`, `ObjectSize(view *ffi.ValueView) (uint64,
int32)`.

D-05's existing codebase precedent for casting native unsigned counts to Go int (materializer_fastpath.go,
`int(frame.ChildCount)`) — Array.LenErr/Object.SizeErr cast the native `uint64` count to Go `int` the
same way.

Upstream cost/saturation facts (verified directly against third_party/simdjson source in plan 12-02,
already landed): `array::at(size_t)` is an O(n) linear scan via the array iterator (NOT random
access — simdjson's tape has no per-element offset table); `array::size()`/`object::size()` read a
24-bit tape field (`JSON_COUNT_MASK = 0xFFFFFF`) that silently saturates at 16,777,215 direct
children.
