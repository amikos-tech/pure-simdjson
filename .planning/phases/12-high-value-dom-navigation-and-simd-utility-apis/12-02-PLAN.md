<objective>
Add indexed array access (`Array.At`, DOM-04) and constant-time array/object size helpers
(`Array.Len`, `Object.Size`, DOM-04) to the native stack, reusing the ABI/status-code foundation
plan 12-01 already landed.

Purpose: complete the DOM-04 native surface. `Array.At` is a one-shot resolve-then-register call
identical in shape to plan 12-01's navigation functions; `Array.Len`/`Object.Size` are simpler O(1)
scalar reads with no descendant-view registration (they return a count, not an Element).
Output: three new native exports (`pure_simdjson_array_at`, `pure_simdjson_array_len`,
`pure_simdjson_object_size`) wired end-to-end and covered by Rust integration tests.
</objective>

| T-12-04 | Denial of Service | Array.At called in a loop over a huge array (O(n) per call, O(n^2) full traversal) | accept | Documented honestly in the Go doc comment (plan 12-08); this is upstream's own array::at cost, not a project-introduced amplification, and callers are steered to Array.Iter() for full traversal |

| T-12-06 | Tampering | Out-of-bounds index passed to array_at | mitigate | Upstream's own array::at bounds-checks via a linear scan and returns INDEX_OUT_OF_BOUNDS, mapped through the existing map_error case from plan 12-01; no unchecked pointer arithmetic on the Rust/C++ side |
