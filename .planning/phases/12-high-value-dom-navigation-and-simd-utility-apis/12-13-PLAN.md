<objective>
Make the ABI 1.3 loader's mandatory binding surface actually complete by moving the two earlier
public allocator-telemetry exports out of optional registration, and prove both directions
(missing-reset, missing-snapshot) fail closed before any cache installation.

Purpose: 12-VERIFICATION.md failed 12-11 T5 because `internal/ffi/bindings.go` registers
`pure_simdjson_native_alloc_stats_reset` and `pure_simdjson_native_alloc_stats_snapshot` through
`registerOptionalFuncWithRegistrar` after the mandatory symbol loop, so an artifact claiming ABI 1.3
but missing either symbol still binds and gets cached. Both `docs/ffi-contract.md` (lines ~209-215,
~307-309) and `tests/abi/check_header.py`'s required-symbol set already treat these two exports as
part of the mandatory earlier-ABI-1.3 surface — only the Go loader's binding table and its two test
fixtures (`internal/ffi/bindings_test.go`'s `abi13RequiredSymbols`,
`library_loading_test.go`'s `abi13MandatoryFixtureSymbols`) disagree, and both fixtures omit the two
symbols entirely, so the existing "complete ABI 1.3 surface" tests were modeling an incomplete
surface as complete. No documentation change is needed; only `internal/ffi/bindings.go` and its two
test fixtures are wrong.
Output: both allocator-telemetry exports are mandatory bindings; `abi13RequiredSymbols` and
`abi13MandatoryFixtureSymbols` include them; two new regressions prove each one's absence fails
binding before cache installation, without breaking the existing ABI 1.2 rejection or ABI 1.4
additive-compatibility behavior.
</objective>
