```go
func newParserWithConfig(config parserConfig) (*Parser, error) {
	kernelMu.Lock()
	defer kernelMu.Unlock()
	library, err := activeLibrary()
	if err != nil { return nil, err }
	handle, rc := library.bindings.ParserNewConfigured(config.maxCapacity, config.maxDepth)
	if err := wrapStatus(rc); err != nil { return nil, err }
	kernelSelectionLocked = true
	...
}
```
The CPU-unsupported check happens NATIVELY inside the bindings call (plan 12-04's
implementation_selection_state() check in C++, plus the Rust reject_fallback_implementation() test
hook) — `wrapStatus(rc)` already turns `PURE_SIMDJSON_ERR_CPU_UNSUPPORTED` into `ErrCPUUnsupported`
via sentinelForStatus. Utility state must be recorded before wrapping a post-call status:
ErrCPUUnsupported means the native gate rejected before locking; every other status reachable after
Go prevalidation means the gate passed and native selection is locked, including Minify's
ErrInvalidJSON. Prevalidation and activeLibrary errors occur before the native call and leave state
unlocked.
