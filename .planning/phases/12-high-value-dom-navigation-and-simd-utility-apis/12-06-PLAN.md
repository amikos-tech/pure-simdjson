surprising) behavior honestly.

```go
func (o Object) GetField(key string) (Element, error) {
	doc, err := o.element.usableDoc()
	if err != nil { return Element{}, err }
	if ffi.ValueKind(o.element.view.KindHint) != ffi.ValueKindObject { return Element{}, ErrWrongType }
	view, rc := doc.parser.library.bindings.ObjectGetField(&o.element.view, key)
	runtime.KeepAlive(doc)
	if err := normalizeIteratorError(doc, rc); err != nil { return Element{}, err }
	return Element{doc: doc, view: view}, nil
}
```
AtPointer/AtPath use plain `wrapStatus(rc)`, not `normalizeIteratorError` (that helper exists
specifically for iterator-lease semantics, which navigation calls do not have) — and they perform NO
kind pre-check before the FFI call (upstream `at_pointer`/`at_path` dispatch on kind internally and
work on scalars when the pointer/path is empty).

```go
func (e Element) usableDoc() (*Doc, error) {
	if e.doc == nil { return nil, ErrInvalidHandle }
	if e.doc.parser == nil || e.doc.parser.library == nil || e.doc.parser.library.bindings == nil {
		return nil, ErrInvalidHandle
	}
	if e.doc.isClosed() { return nil, ErrClosed }
	return e.doc, nil
}
```

Documented upstream pitfalls this plan's doc comments MUST state honestly (from RESEARCH.md, backed
by direct reading of third_party/simdjson/include/simdjson/jsonpathutil.h and element-inl.h — do not
soften or omit these):
- Pitfall 1: AtPath's bracket-key form is NOT quote-aware. `AtPath(".obj['foo']")` looks up the
  literal five-character key `'foo'` (including both quote characters), not `foo`. Unquoted bracket
  form `AtPath(".obj[foo]")` correctly looks up key `foo`. This is an upstream asymmetry (the
  wildcard code path DOES strip quotes; the plain at_path path does not) — document it as fact, not
  as a bug this project can silently "fix".
- Pitfall 2: AtPath requires a leading `.` or `[` (after an optional leading `$`). `AtPath("name")` is
  ALWAYS invalid (ErrInvalidPath); must be `AtPath(".name")` or `AtPath("$.name")`.
  `AtPath("")` is also invalid.
  `AtPath("$")` / `AtPath(".")` behavior is upstream's own edge-case handling — document per the test
  output.
- Pitfall 3: a trailing separator navigates into a literal empty-string key on the CHILD, not a
  no-op. `AtPointer("/a/")` on `{"a": 1}` returns ErrElementNotFound;
  on `{"a": {"": "x"}}` it returns the string "x".
- Amended D-02: AtPathAll requires at least one literal `*`; reject wildcard-free input before FFI.
  Valid wildcard branches that are missing, out of bounds, or non-containers are skipped, yielding
  `([]Element{}, nil)` when no branch survives. Branch errors never surface as
  ErrElementNotFound/ErrIndexOutOfRange/ErrWrongType through AtPathAll.
