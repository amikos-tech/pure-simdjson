<objective>
Restore the public `pure_simdjson_minify` `BUFFER_TOO_SMALL` out-parameter contract so a caller
that under-allocates its destination buffer can read the exact required capacity back from
`out_written`, and prove it at both the Rust unit-test layer and the dynamic C smoke layer against
a real built library.

Purpose: 12-VERIFICATION.md failed 12-04 T5 and blocked requirement UTIL-01 because
`runtime::native_minify` converts every non-OK native status into `Err(rc)` and discards the
native `written` value, and `pure_simdjson_minify` only writes `out_written` in the `Ok` branch. A
direct `ctypes` call to the built library returned `rc=6 written=18446744073709551615
dst_unchanged=True expected_written=8` instead of the documented `written=8`. The C++ bridge
(`psimdjson_minify` in `src/native/simdjson_bridge.cpp`) already stores `src_len` into its local
`out_written` before any capacity check and is NOT part of this defect (12-04 T1 verified) — the
break is entirely in the Rust handoff (`src/runtime/mod.rs`) and the public export (`src/lib.rs`).
docs/ffi-contract.md line 257 already documents the correct contract ("On status 6, minify writes
the required conservative capacity (`src_len`) to `out_written`"), so no documentation changes are
needed — only the Rust code and its tests are wrong.
Output: `native_minify`/`pure_simdjson_minify` preserve `(status, written)` together for `OK` and
`BUFFER_TOO_SMALL`; the Rust test and the dynamic C smoke test both assert the required-capacity
value, not just the status code.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Go/C caller -> Rust FFI (`pure_simdjson_minify`) | A caller relies on `out_written` to learn the exact retry buffer size after `BUFFER_TOO_SMALL`; a wrong or untouched value can cause an under-sized retry loop or an unbounded/garbage reallocation if the caller trusts a stale sentinel |
| Rust runtime -> C++ bridge (`native_minify` / `psimdjson_minify`) | Status and required-capacity must round-trip together across the FFI boundary, not be silently split apart by the Rust handoff |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-22 | Tampering | `pure_simdjson_minify` BUFFER_TOO_SMALL out-parameter handoff (`src/runtime/mod.rs`, `src/lib.rs`) | mitigate | `native_minify` returns `(status, written)` as one inseparable tuple; `pure_simdjson_minify` writes `out_written` via direct `ptr::write` (never through `write_out`, whose own return code would clobber a genuine BUFFER_TOO_SMALL) for exactly `OK` and `BUFFER_TOO_SMALL`, and always returns the true native `rc` |
| T-12-23 | Repudiation | Passing test suite that did not assert the decisive value (`tests/rust_shim_minify.rs`, `tests/smoke/ffi_export_surface.c`) | mitigate | Add `assert_eq!(written, input.len())` to the Rust undersized-destination test and an equivalent status+capacity assertion to the dynamic C smoke harness, so a future regression on this exact path fails both gates instead of passing silently |
</threat_model>
